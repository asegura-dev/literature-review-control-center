# Phase notes - v0.7.0, Verify and replay

Branch `v0.7.0-replay`. Decision: ADR-0013, accepted on 2026-09-30, after the maintainer ran the real
scenario. What was run is kept apart from what is assumed; every run below was on Windows 11,
Python 3.12.13, uv 0.10.12.

## What "done" means for this phase

From the roadmap: a replay produces identical outputs, and a re-run is documented as a different
run.

## Observed

With the two features written and no test for them yet, the 162 existing tests passed and the

```

```

### Each kind of damage, named

Tests store a run against the mocked transport, damage it, and assert what `verify` reports:

| Damage | Reported as |
|---|---|
| one byte appended to a stored response | `response-0001.raw: does not match the digest in the log` |
| a stored response deleted | `response-0001.raw: is missing` |
| a file added to a run folder | `extra.txt: is not named by the log` |
| a run folder added | `runs/0099-stray: no log entry names this folder` |
| a record's title edited in the database | `the records in the database do not match the log` |
| a log entry edited to name `../../../protocol.yaml` | refused: `names a response outside the review` |

### Replay

- With the network off in the configuration, `replay` reproduced the run: `logged 2  replayed 2
  identical`, and no request was made.
- With the adapter's derivation replaced by one that returns fewer records, `replay` reported
  `logged 2  replayed 1  DIFFERENT` and exited with code 1.
- With a stored response altered, `replay` refused that run and pointed at `verify`.

### PubMed book records

A synthetic fixture mixes a chapter, a journal article and a whole book. The adapter returns the
three, in that order. The chapter uses its own title and authors, and the whole book uses the
book's.

### The real scenario, run by the maintainer

On 2026-09-30 the maintainer ran both commands over the three runs stored from the real
services. The result was predicted in these notes before it was run, and matched.

```
> lrcc verify prueba
Review prueba: 3 run(s) and 17 stored response(s) checked.
Everything stored matches the log.

> lrcc replay prueba
  0001-20260930T145901Z-arxiv  logged 50  replayed 50  identical
  0002-20260930T150047Z-arxiv  logged 106  replayed 106  identical
  0003-20260930T150053Z-pubmed  logged 2489  replayed 2499  DIFFERENT: the records derived now differ from the ones logged
```

- The two arXiv runs are reproduced from their stored responses. The adapter was refactored
  in this phase, so this also shows the refactor changed nothing it derives.
- The PubMed run replays with the ten book records the first adapter dropped: 2,489 plus 10
  is the 2,499 PubMed reported. They were recovered from disk, without asking PubMed again.

## Assumed, not yet observed

- **That the 2,489 journal records are unchanged.** The PubMed run replays as different
  because ten records were added. The output does not say whether the other 2,489 are the same
  as before the refactor. The synthetic tests say so; the real records have not been compared.
- **That each real book record is read correctly.** The count is right. No one has looked at
  the titles, authors and years derived from the ten real ones.
- **CI for this branch.**
