# Phase notes - v0.1.0, Configuration, protocol and workspace

Branch `v0.1.0-init-and-validate`. Decision: ADR-0010, accepted on 2026-09-29, which merged the
roadmap's v0.1.0 and v0.2.0 rows. What was run is kept apart from what is assumed; every run
below was on Windows 11, Python 3.12.13, uv 0.10.12.

## What "done" means for this phase

From the roadmap:

- an empty required value is a clear error, never a silent default;
- a workspace inside a repository is refused, and so is a path that escapes the boundary.

From ADR-0010:

- `lrcc init` and `lrcc validate` work end to end;
- the reported digest is the file's SHA-256.

### The real scenario

The installed `lrcc` entry point was run through `.\run.ps1 run lrcc`, not through the test
runner. The development workspace was an empty folder in a temporary directory, outside OneDrive
and outside any repository.

- `lrcc` with no arguments printed the help, listing `init` and `validate`.
- `lrcc init example --config <file>` created the review and printed
  `sha256 df76b348d57e0273292aec6e413743d21dc27e25b940c835e666e33f0649bc2f`.
- `lrcc validate example`, with the configuration named by `LRCC_CONFIG`, reported:
  - the protocol valid;
  - `INC1, INC2`, `EXC1, EXC2`;
  - sources `arxiv, pubmed`;
  - the same digest.
- `Get-FileHash -Algorithm SHA256` over the protocol printed the same digest,
  `df76b348…49bc2f`.
- A configuration naming this repository's own folder as the workspace was refused:

  ```
  error: workspace C:\...\literature-review-control-center is inside the git working tree C:\...\literature-review-control-center
    - licensed content must never be one `git add` away from a repository (ADR-0006)
    - choose a folder outside every repository
  ```

- The configuration file for the run was written by Windows PowerShell 5.1's `Set-Content
  -Encoding utf8`, which adds a UTF-8 byte-order mark. LRCC read it without complaint, which is
  why accepting the mark is recorded in ADR-0010.

### Links out of the workspace

On this machine the test created a real directory junction with `_winapi.CreateJunction`. A path
through it was refused, and no test was skipped.

## Assumed, not yet observed

- **CI for this branch.** It runs when the pull request is opened. On Linux, the link test uses a
  symlink instead of a junction.

## Pending, outside this phase's scope

- **The tag `v0.0.1`** waits for its closing commits to reach `main`. They travel in this branch
  too.
- **Selecting the interpreter in VS Code.** The editor flags pydantic, rich and typer as "not
  installed" because it is not pointed at `%USERPROFILE%\.venvs\lrcc`. It is an editor setting,
  and nothing in the gate depends on it.
- **The protocol format has no amendment mechanism yet.** The brief's "versioned protocol
  amendments" arrive with screening (v0.10.0). Until then, a changed protocol is simply a new
  digest.
