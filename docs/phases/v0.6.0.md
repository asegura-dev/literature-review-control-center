# Phase notes - v0.6.0, check-query

Branch `v0.6.0-check-query`, built after v0.7.0 and released with it, in 0.7.0. Decision: ADR-0014,
**Proposed** on 2026-09-30. What was run is kept apart from what is assumed; every run below was
on Windows 11, Python 3.12.13, uv 0.10.12.

## What "done" means for this phase

From the roadmap: the string retrieves the whole gold set, or every gap is recorded with its
reason.

## Inputs from the maintainer

The maintainer gave the question and framework of the first real review, a gold set of 14 works,
five frontier cases, and version 2 of the PubMed and arXiv strings. Following the rule that
protocols live in the workspace and never in this repository, they were written as drafts outside
both, in the maintainer's configuration folder. The protocol's criteria and extraction fields are
proposals for the maintainer to decide.

### A trap in the maintainer's own gold set

The first validation of the draft gold set failed on `arxiv: 2508.02104`. Unquoted, YAML reads
the identifier as a number. A number cannot be turned back into an identifier safely, because
`2508.02100` would become `2508.021`. The value is now refused with a message saying to quote it,
and the draft was quoted.

### Errors reported once

The same validation first reported each bad identifier twice: once per branch of the optional
type. When the only work was invalid, it also reported the list as empty, which was false. Both
were fixed, and the tests now assert exactly one line per problem.

### CI

Pull request #4 ran the gate on Ubuntu and Windows, and it passed. So did `main` after the merge.
It was the first green CI run for everything from v0.1.0 on, once pull request #3 had fixed the
help test.

### The first real check, run by the maintainer

On 2026-09-30 the maintainer installed the draft protocol and gold set in the review's folder,
validated the protocol, and ran the check against both real services. The gold set's contents
are the maintainer's private research material and are not recorded here; only counts are.

| Source | Gold works | Retrieved | Missed | Not indexed | Unknown |
|---|---|---|---|---|---|
| PubMed | 14 | 12 | 0 | 0 | 2: one work with no identifier, one known only by arXiv id |
| arXiv | 14 | 1 | 0 | 0 | 13: works known only by DOI, and the one with no identifier |

- PubMed's `[doi]` field found every gold work that has a DOI, which was the open question.
- The strings reported 253 records on PubMed and 245 on arXiv, seen as previews.

## Assumed, not yet observed

- **That the PubMed result measures the string.** By the maintainer's own account most gold works
  came from a PubMed run of an earlier version of the string, so 12 of 12 is partly circular.
- **That the check can report a miss, or a work a source does not hold, against the real
  services.** Every state seen so far was "retrieved" or "unknown". The synthetic tests show the
  other two states. A control against the real services, with a work each source does not hold
  and one the string should not retrieve, would show them in the real services too.
- **arXiv coverage of the gold set.** Only one gold work has an arXiv identifier, so the arXiv
  check says little until more gold works carry theirs.

## Pending, outside this phase's scope

- **Storing a check** with its date, the string's digest and each state, so a paper can cite it.
- **Independent gold works.** The maintainer will add works found through forward citations,
  which do not come from PubMed.
- **The frontier cases.** They are for calibrating the criteria in the screening pilot (v0.10.0).
