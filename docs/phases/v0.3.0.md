# Phase notes - v0.3.0, One HTTP client and the first two sources

Branch `v0.3.0-search`. Decision: ADR-0011, accepted on 2026-09-30, which merged the roadmap's
v0.3.0 and v0.4.0 rows. What was run is kept apart from what is assumed; every run below was on
Windows 11, Python 3.12.13, uv 0.10.12.

## What "done" means for this phase

From the roadmap:

- the gate fails if anything but the one client can reach the network;
- the client refuses an unlisted host before sending;
- `search` runs offline against fixtures.

## Observed

### The gate

```
.\run.ps1 run ruff check .          All checks passed!
.\run.ps1 run ruff format --check . 66 files already formatted
.\run.ps1 run mypy                  Success: no issues found in 43 source files
.\run.ps1 run pytest                144 passed; coverage 97.40%, threshold 95% reached
```

### No request left the machine

- `respx` replaces the transport in every client and source test. A request to a route that was
  not mocked raises.
- A fixture in `tests/conftest.py` makes `socket.connect` fail for every test, and a test
  asserts that it does.
- The refusal tests define no route and assert a call count of zero: network off, a host not
  listed, a look-alike host (`example.org.evil.test`), plain HTTP, and a non-default port.

### The egress check, failing on purpose

`tests/test_egress.py` writes a temporary package with a second module that imports `httpx`,
`urllib.request`, `http.client` or `socket`, and asserts each is named. Its first version named
one import twice; the parametrized cases caught that before it was trusted.

### The real command, for its refusals only

The installed `lrcc` entry point was run through `.\run.ps1 run lrcc`, against the development
workspace in a temporary directory.

```
> lrcc search example --source arxiv          (configuration without a network section)
error: the network is off, so nothing was requested
  - set network.enabled to true in the configuration to allow requests

> lrcc search example --source arxiv          (network on, only eutils.ncbi.nlm.nih.gov listed)
error: export.arxiv.org is not an allowed host, so nothing was requested
  - only hosts named under network.hosts in the configuration are contacted
```

## Assumed, not yet observed

- **A real search.** No request was made to PubMed or arXiv while building this phase. The
  adapters were written from the services' documented formats and tested only against the
  synthetic fixtures. The first real search is the maintainer's, and it may show differences
  the fixtures do not have.
- **The rate limits.** `min_interval` values of 0.4 s for PubMed and 3 s for arXiv follow the
  limits those services publish. They were not measured.
- **CI for this branch.** It runs when the pull request is opened.

## Fixtures

The four files under `tests/fixtures/` are synthetic: written by hand, with invented titles,
authors, abstracts, identifiers and DOIs. Only their shape follows the sources' formats. The
maintainer reviews them before they are committed.

## Pending, outside this phase's scope

- **Paging beyond `--limit`.** PubMed's `esearch` returns at most 10,000 identifiers per request,
  and arXiv pages with `start`. A full run needs paging, and belongs with the stored runs of
  v0.5.0.
- **PubMed's optional API key and contact e-mail.** NCBI asks tools to send an e-mail address,
  and a key raises the limit from three to ten requests per second. Both wait for the secrets
  handling of v0.8.0, or for an earlier decision if the first real review needs them.
- **The tags `v0.0.1` and `v0.1.0`** wait for their commits to reach `main`.
