# Phase notes - v0.9.0, Deduplication

Branch `v0.9.0-dedupe`. Decisions:

- ADR-0017, the exact step, **Proposed** on 2026-10-01;
- ADR-0018, the person's step, **Proposed** the same day. Its options were decided by the
  maintainer: a CSV round trip, the reviewer in the configuration, a threshold of 0.80.

Both build on ADR-0006, which decided the `work_id` and the catalog. What was run is kept apart
from what is assumed; every run below was on Windows 11, Python 3.12.13, uv 0.10.12.

## What "done" means

From ADR-0017, the first part:

- records join works through shared identifiers, and every join keeps its reason;
- a `work_id`, once given, never changes;
- a new run is joined to the works that exist;
- a conflict or a collision stops the pass, and nothing is written.

From ADR-0018, the second part:

- pairs of works with similar titles are proposed, never merged without a person;
- each decision is recorded with its reviewer in a hash-chained log, and a correction is a new
  entry;
- the review counts groups: works joined by a person's `same`.

test failed every time:

| Rule broken | Tests failed |
|---|---|
| refuse a record that names two works | 2 |

| the family name before trailing initials | 2 |

The last rule had no test at first: every command test kept one protocol throughout. A test that
changes the protocol between two imports was added first, and only then was the rule broken.

### A defect found by trying the command

`lrcc dedupe` was run in a scratch workspace, on a review holding an arXiv run stored by the
previous version's code and an import made earlier under the arXiv source. That import had used
a Scopus-shaped file, so its records' own identifiers were EIDs, and they were registered as
`arxiv:2-s2.0-...`. That way a RIS digest or an EID imported under arXiv would count as a stable
arXiv identifier. Such identifiers are now typed `arxiv-record:`, and a test holds it. A second
pass on the same review linked nothing, and `status` still verified.

### Real records, in a scratch workspace

Before the command touched the real review, where links can never be edited, the maintainer
agreed to try it on real records. The three definitive searches were stored again in a scratch
workspace, with the maintainer's keys and protocol version 6, and gave the same counts: 500,
223 and 245. `lrcc dedupe` then linked them:

| | Count |
|---|---|
| records | 968 |
| works | 886 |
| duplicates removed, all joined by DOI | 82 |
| PubMed records already met in IEEE Xplore | 67 |
| arXiv records already met in IEEE Xplore or PubMed | 15 |
| conflicts, collisions, works named from a title | 0 |

**The joins hold.** In 76 of the 77 joined groups, the records' normalized titles agree at 0.99
or more (difflib's ratio). The 77th, at 0.89, is an arXiv preprint whose title changed when
it was published, under the same DOI.

**What the exact step leaves apart.** Every pair of works from different sources was compared on
normalized titles. Titles are not recorded here; they are the databases' content.

| Similarity | Pairs |
|---|---|
| 0.95 - 1.00 | 34, of which 32 identical |
| 0.90 - 0.95 | 1 |
| 0.80 - 0.85 | 1 |
| 0.75 - 0.80 | 7 |
| 0.70 - 0.75 | 18 |
| 0.65 - 0.70 | 79 |
| 0.60 - 0.65 | 229 |

Reading the pairs from 0.75 up:

- the 32 identical titles share the first author and lie 0 to 3 years apart. They are arXiv
  preprints, which carry no DOI, beside their published versions;
- at 0.94, two different papers by the same group, one on prognosis and one on diagnosis;
- at 0.82, by every sign, a preprint whose title changed when it was published;
- at 0.80, two titles by the same first author, two years apart, that read as a conference paper
  and its journal extension: two publications;
- below 0.80, the first authors mostly differ.

So about 35 duplicates remain for the fuzzy step. A title score alone cannot tell them apart from
the false ones in the same band, which is why a person confirms each pair. These numbers are the
measurement the fuzzy step's threshold starts from.

### The second part: a person confirms what titles propose

Built the same day, from ADR-0018: `lrcc candidates`, `lrcc decide`, the decisions' log, groups,
and `reviewer` in the configuration.

- **Each rule was broken on purpose, and a test failed each time.** There were fourteen:
  - the contradiction refusal;
  - decided pairs left out, and grouped works left out;
  - the published version kept;
  - the reviewer required;
  - an unchanged decision not recorded again;
  - formula escaping;
  - the latest decision in force;
  - `verify` checking the chain;
  - never overwriting the file;
  - a pair twice in one file;
  - the person's duplicates counted;
  - each of the two cheap bounds, made too strict.
- **One mutation first failed to run, not to be caught.** `verify.py`, checked out on Windows,
  has CRLF line endings, so a pattern written with `\n` did not match. Rewritten without the line
  ending, it was caught.
- **On the real records of the scratch workspace**, `candidates` proposed 37 pairs at 0.80 or
  more: 33 at 1.0, then 0.953, 0.936, 0.82 and 0.811. The measurement foresaw that size and
  shape. Some scores differ a little from it, because the measurement compared one title per work
  and the listing compares every title of a work.
- **Where the time goes.** The first version took 20 seconds in `dedupe` and in `candidates`
  alike. Timing each step showed loading the review takes 0.1 seconds, and comparing the 392,055
  pairs of titles the rest. Two cheap upper bounds now come first:
  - the lengths;
  - the shared characters, exact for normalized titles.

  About 75,000 pairs still need the full ratio, at 147 microseconds each. A test checks the
  listing against scoring every pair. `dedupe` no longer lists pairs, and takes 0.6 seconds;
  `candidates` takes 14.6.
- **A defect found while gathering evidence for the maintainer.** The abstracts of pairs that
  plainly began alike scored between 0.01 and 0.04. `difflib`'s `autojunk` drops a text's most
  frequent characters once it reaches 200 characters, so a 259-character title nearly equal to
  another scored 0.2 instead of 0.973. `autojunk` is now off, and a test holds it. The test
  fails with `autojunk` on. One title of the review reaches 200 characters, and the listing is
  unchanged: the same 37 pairs, with the same scores.
- **The maintainer ran both parts on the real review** on 2026-10-01. Its 1,936 records, runs 1
  to 6, linked into 886 works. The current protocol's runs hold 968 records, and 82 duplicates
  were removed by identifiers. The same 37 pairs were written to the maintainer's file, and the
  `work_id`s match the scratch workspace's, because the records came in the same order.
- **No decision was recorded in the scratch workspace or anywhere real.** The tests record
  decisions on synthetic works. The decisions on the review's 37 pairs are the maintainer's.
